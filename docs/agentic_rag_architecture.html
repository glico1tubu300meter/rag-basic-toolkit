Agentic RAG(LangGraph版)のしくみ

scripts/agentic_query.py の実装解説。単発のquery.py(検索して1回で答えるだけ)の 弱点を補うため、検索者・批評者・判定者の3役をLangGraphのStateGraphとして実装している。

グラフ構造

「再検索」は独立した人格ではなく、批評者が提案したクエリを使った機械的なFAISS検索に過ぎない。 LLM呼び出しは①検索者は無し(検索のみ)、②批評者、③判定者の計2回(1ラウンドあたり)。

State(状態)の設計

class GraphState(TypedDict):
    question: str        # 元の質問(変わらない)
    query: str            # 現在の検索クエリ(初回は question、以降は批評者の提案)
    passages: list[dict]  # 全ラウンドで蓄積された検索結果
    critic_text: str      # 直近の批評者の判定文
    round: int             # 現在のラウンド数(0始まり)
    answer: str            # 最終回答(judgeノードでのみ書き込み)

1つのStateを全ノードが読み書きするため、 複数の変数を手動で受け渡しするコードに比べ、渡し忘れによるバグが起きにくい。

load_llm() の詳解

Qwen2.5-7B-Instructを4bit量子化でロードし、LangChainのChatModelとして使える形に3段階でラップしている。

def load_llm(gen_model_name):
    bnb_config = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_quant_type="nf4",
        bnb_4bit_compute_dtype=torch.float16,
        bnb_4bit_use_double_quant=True,
    )
    tokenizer = AutoTokenizer.from_pretrained(gen_model_name)
    model = AutoModelForCausalLM.from_pretrained(
        gen_model_name,
        quantization_config=bnb_config,
        device_map={"": 0},
        dtype=torch.float16,
        disable_mmap=True,
    )
    hf_pipe = pipeline(
        "text-generation", model=model, tokenizer=tokenizer,
        max_new_tokens=350, do_sample=True, temperature=0.5, top_p=0.9, return_full_text=False,
    )
    llm = HuggingFacePipeline(pipeline=hf_pipe)
    return ChatHuggingFace(llm=llm, tokenizer=tokenizer)

1. BitsAndBytesConfig

引数意味
load_in_4bit=True重みを4bitに量子化してロードする。VRAM 11GBのGPUで7Bモデルを動かすための必須設定
bnb_4bit_quant_type="nf4"NormalFloat4(NF4)方式。正規分布に従う重みの分布に最適化された4bit表現
bnb_4bit_compute_dtype=torch.float16Pascal世代GPU(GTX 10xx等)はbfloat16の演算に対応していないため、必ずfloat16を指定する必要がある
bnb_4bit_use_double_quant=True量子化のスケール定数自体もさらに量子化し、メモリを追加で数%削減する

2. モデルロード

引数意味
device_map={"": 0}モデル全体をGPU 0番に固定配置(単一GPU環境)
disable_mmap=Trueネットワークドライブ上のモデルをmmapでロードするとSegmentation faultが起きる既知の問題への対策

3. LangChainラッパーへの2段変換

HuggingFacePipelineがtransformersのpipelineをLangChainのRunnableに適合させ、 ChatHuggingFaceがその上に被さってtokenizer.apply_chat_templateを 自動適用することで、SystemMessage/HumanMessageのようなチャットメッセージ列を 直接扱えるようになる。

実行結果(実測)

質問「RAGとは何ですか？」で data/sample_corpus.jsonl のインデックスに対して実行。

段階結果
search (round 0) 「RAG」「FAISS」「LoRA」の技術解説パッセージを3件取得
critic (round 0) 「十分」「追加検索クエリ: なし」と正しく判定、1ラウンドで終了
judge 検索結果[1]の内容を正確に反映した簡潔な回答を生成
